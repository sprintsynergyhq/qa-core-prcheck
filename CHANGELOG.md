- `src/diff/parse.ts`: parser that turns a git unified diff into a sorted list of changed files. It reads hunks by their line counts and handles renames, copies, binary files, mode changes, quoted paths and paths with spaces.
- `src/diff/classify.ts`: built-in rules that give each changed path one of ten file classes.
- `src/diff/git.ts`: git source that diffs the merge base of two refs against the head through `execFile` with fixed flags, with plain errors for bad refs, non-repos, unrelated histories and shallow clones.
- `src/diff/format.ts`: text and JSON formatters for the diff result.

- M1 (focused tests): every Playwright run passes `--forbid-only`, both the `--list` inventory (`src/inventory/list.ts`) and the test run (`src/run/command.ts`), so a `test.only` gives `Error`, exit 2, in every environment and can never give `Passed`. `CI` is no longer removed from the Playwright environment (`src/playwright/cli.ts`, 8 keys left); it starts no git in Playwright 1.60.0.
- S1 (sticky comment author): the `comment` command reads `PRCHECK_COMMENT_AUTHOR` (default `github-actions[bot]`) and edits only that author's comment with the matching user type; a person's login is accepted only when `GET /user` returns it. A comment created under another login prints a `Note:` line and, in GitHub Actions, a warning. `action.yml` gains the `comment-author` input, passed through `env:` only.
- S2 (API timeout and retry): each GitHub API request is stopped after 30 seconds; `GET` and `PATCH` are retried at most twice after a network error, a timeout, a 5xx, a 429 or a rate limited 403, with the wait GitHub asks for (60 seconds when it names none for a rate limit) or 2 seconds times the attempt; a wait over 60 seconds fails at once. A `POST` is never sent twice without a fresh list of comments between them. `GitHubError` gains `method`, `rateLimited`, `retryable` and `waitMs`.
- S3 (read-only token): a 403 on creating or updating the comment that is not a rate limit prints `Skipped` and a warning and exits 0; other API errors stay exit 2. New `comment --help` text.
- S4 (deleted spec): a spec the change deletes gets a first Warnings row in the summary, and in mode `none` the lead says how many spec files the PR deletes. The old path of a renamed spec now has the reason `Spec renamed: <old> to <new>` (`src/impact/map.ts`), so a rename is never reported as a deletion.
- Tests: real Playwright cases for a focused test with and without `CI`, a control that `CI` reaches the test and no git runs, retry, wait, timeout and POST rule cases with an injected sleep, author and read-only token cases for the comment command, and the `spec-deleted` summary golden. `README.md`, `CLAUDE.md` (invariants 15 and 22) and `STATE.md` follow.
